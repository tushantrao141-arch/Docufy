Features

Everything You Need for
Intelligent Documentation

Docufy is not just another README generator. It is a context-engineered AI agent built on principles from the ACE framework.

🧠

Context Engineering

Every stage of the pipeline is an input construction problem. Prompts are the primary engineering artefacts — not boilerplate wrappers.

🗜️

Intentional Compaction

Two-stage pipeline compresses raw source files into dense summaries. Raw code never touches the final context window — only distilled signal.

🤖

Subagent Isolation

Each file summary call is a bounded inference call. The parent pipeline only receives compacted output — keeping context clean and focused.

⚡

Incremental Updates

Change one file? Only that slice of the cache is invalidated. No need to reprocess the entire codebase — just the stale context.

📦

Smart Caching

File summaries persist in .docufy/cache.json. Subsequent runs resume from compact context — not raw files.

🔧

Model Flexibility

Default to Groq's fast inference or override per-run with any supported model. Switch between LLMs without changing config.

Workflow

Research → Plan → Implement
Built Into the Pipeline

Inspired by the ACE Framework from Dex Horthy, Docufy's agentic pipeline follows the three-phase workflow that makes AI agents actually work.

1
Research Phase

docufy init

Scans your repository respecting .gitignore rules. Discovers all relevant files and compiles findings into docufy.yaml — the structured context manifest. No inference happens here; this is pure discovery.

2
Stage 1 — Batch Summarization

docufy run — Per-File Compression

Each file passes through a bounded summariser agent. A 500-line source file becomes 3–4 sentences of dense, structured signal. Summaries are cached to .docufy/cache.json — the compaction artefact.

3
Stage 2 — Final Synthesis

docufy run — README Generation

All summaries (never raw files) are assembled into the final context window. The agent synthesises a comprehensive, professional README.md. Previous README is safely backed up.

4
Selective Refresh

docufy update <path>

When a file changes, only that slice of the compaction pipeline re-runs. Use docufy update . to regenerate README from existing cache without any new API calls.

CLI Reference

Four Commands.
That's All You Need.

docufy init Research

Scan the repository, build the context manifest, create docufy.yaml. Safe to re-run anytime.

docufy run Generate

Execute the full agentic pipeline. Summarise every file, then synthesise the final README.

docufy update <path> Refresh

Targeted cache refresh. Recompute one file or regenerate README from existing cache.

docufy models Discover

List all available Groq models with context window sizes. Pick the right model for your codebase.

Architecture

Context Engineering
Under the Hood

Every design decision maps to a principle from the ACE Framework. Here's how the pieces fit together.

📁

docufy/pipelines/

CLI supervisor orchestrating the init → run → update workflow. Entry point for all commands.

⚙️

docufy/components/

Core logic for each CLI command — init.py, run.py, update.py, models.py, and config.py.

📝

docufy/prompts/

Version-controlled prompt files treated as source code — batch_summary.txt and final_summary.txt.

🔌

docufy/utils/

LLM client, file extraction, caching, scanning, logging — all the supporting infrastructure.

📐

docufy/schema/

Pydantic models for LLMConfig, FileSummaries, and ReadmeResponse — structured data contracts.

🗄️

.docufy/cache.json

The compaction artefact — stores distilled file summaries so agents resume from clean, compact context.

Stateless LLM — input is everything Prompts treated as primary engineering artefacts
Frequent Intentional Compaction Two-stage pipeline: raw files → summaries → synthesis
Subagent Context Isolation Per-file summariser keeps raw content out of synthesis
Research → Plan → Implement init (discover) → run (synthesise) → update (replan)
